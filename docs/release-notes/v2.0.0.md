2.0 is a rewrite: 1.x calculated offsets without DST and assumed UTC for values without a zone.

```
dotnet add package SolTechnology.DateTimeZone
```

- `DateTimeZone` holds a `DateTimeOffset` and a `TimeZoneInfo`; the offset is always the zone's offset at that point in time
- equality by point in time; `SameRepresentation` and `DateTimeZoneComparer.Representation` when the zone matters
- point-in-time arithmetic (`AddHours`, `Add(TimeSpan)`) and calendar arithmetic (`AddDays`, `AddMonths`, `AddYears`, `AtTime`)
- `ClockChange` (`PreviousOffset`, `NewOffset`, `Throw`) for a time that the clock skipped or showed twice on the night of a DST change, also for base-offset changes like Samoa 2011
- `UnzonedDateTime` for a date and time without a zone
- RFC 9557 text, `System.Text.Json` converters
- `Zone`, a name with a static member for every canonical IANA zone (`Zone.EuropeWarsaw`), generated from tzdb; it holds the ID, so it is stable across versions; `TimeZoneInfo` overloads next to it, no string overloads; `Zones.Resolve(string)` for IDs from configuration (IANA, Windows, aliases written in canonical form); clear errors without tzdata or in invariant mode
- net8.0 and net10.0; 128 unit tests, plus a comparison with NodaTime around every transition 1972-2025 in 22 zones

Breaking changes against 1.x: the whole API. `ZoneSelector` is gone (`Zone.EuropeWarsaw` or `Zones.Resolve`), `DateTimeZone(DateTime)` is `FromDateTime` and rejects `Kind.Unspecified`, `Now`/`UtcNow` are methods with an optional `TimeProvider`, `Add(TimeOnly)`/`Add(DateOnly)` are removed (`AtTime` replaces the first).

Known limits: zones come from the OS (no tzdata in chiseled or distroless images), Windows has less tz history than Linux, offsets before 1972 can differ from other libraries by seconds. The README has the full list.
