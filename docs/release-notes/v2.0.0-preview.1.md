First preview of 2.0. It is a rewrite: 1.x calculated offsets without DST and assumed UTC for values without a zone.

```
dotnet add package SolTechnology.DateTimeZone --prerelease
```

- `DateTimeZone` holds a `DateTimeOffset` and a `TimeZoneInfo`; the offset is always the zone's offset at that instant
- equality by instant; `SameRepresentation` and `DateTimeZoneComparer.Representation` when the zone matters
- instant arithmetic (`AddHours`, `Add(TimeSpan)`) and calendar arithmetic (`AddDays`, `AddMonths`, `AddYears`, `AtTime`)
- `GapPolicy` / `OverlapPolicy` for wall times that don't exist or exist twice, including base-offset changes like Samoa 2011
- `UnzonedDateTime` for a date and time without a zone
- RFC 9557 text, `System.Text.Json` converters
- IANA and Windows zone IDs, aliases written in canonical form; clear errors without tzdata or in invariant mode
- net8.0 and net10.0; 122 unit tests, plus a comparison with NodaTime around every transition 1972-2025 in 22 zones

Breaking changes against 1.x: the whole API. `ZoneSelector` is gone (use IANA IDs or `Zones.Resolve`), `DateTimeZone(DateTime)` is `FromDateTime` and rejects `Kind.Unspecified`, `Now`/`UtcNow` are methods with an optional `TimeProvider`, `Add(TimeOnly)`/`Add(DateOnly)` are removed (`AtTime` replaces the first).

Known limits: zones come from the OS (no tzdata in chiseled or distroless images), Windows has less tz history than Linux, offsets before 1972 can differ from other libraries by seconds. The README has the full list.
